# Specification: Auto-Handling of Benchmark Configs & Evidence Logs

- **Status**: Implemented / Specification
- **Author**: diamondburned, Jetski
- **Date**: August 12, 2026

## 1. Objective & Overview

This document specifies the auto-handling pipeline for secondary configuration
files (`config.yaml`, `run_metadata.yaml`) and verification logs/metrics
(`*.log`, `summary_prometheus_metrics.json`) generated by benchmark suites such
as **`inference-perf`**, **`llm-d-benchmark`**, and **`uBench`**.

When contributors upload benchmark report directories into Prism, secondary
files are auto-detected, optimal `data:` URIs are constructed, and content is
mapped directly into Prism's existing `manifests` and `evidence` payload
dictionaries without requiring user intervention or schema modifications.

---

## 2. Ingestion & Classification Matrix

When a directory or set of files is staged for upload in Prism:

| Benchmark Tool                  | Detected File Pattern                    | Payload Field                            | Encoding            | ZIP Archive Target Path              |
| :------------------------------ | :--------------------------------------- | :--------------------------------------- | :------------------ | :----------------------------------- |
| **`inference-perf` / `uBench`** | `config.yaml` / `config.yml`             | `payload.manifests["config.yaml"]`       | Optimal `data:` URI | `<archive_name>/config.yaml`         |
| **`llm-d-benchmark`**           | `run_metadata.yaml` / `run_metadata.yml` | `payload.manifests["run_metadata.yaml"]` | Optimal `data:` URI | `<archive_name>/run_metadata.yaml`   |
| **Prometheus Metrics**          | `*_prometheus_metrics.json`              | `payload.evidence["<filename>"]`         | Optimal `data:` URI | `<archive_name>/evidence/<filename>` |

> **Note on Raw Log Files (`*.log`)**: Large execution log files (`*.log`) are
> explicitly excluded from automatic data URI embedding during directory
> ingestion to prevent browser `localStorage` payload bloat. Remote log URLs
> (e.g. `gs://...` or `https://...`) or smaller verification files can still be
> manually attached to `payload.evidence`.

---

## 3. Data URI Encoding Optimization Scheme

To store inline file content without adding new schema fields to
`PrismResultPayload`, file contents are encoded into `data:` URIs.

For each file, both Base64 and Percent-Encoding (`encodeURIComponent`) URIs are
generated:

- **Base64 URI**: `data:<mime_type>;base64,<base64_data>`
- **Percent-Encoded URI**: `data:<mime_type>;charset=utf-8,<url_encoded_data>`

The ingestion pipeline calculates string lengths for both variants and assigns
the shorter URI to `manifests` or `evidence`.

### Why Percent-Encoding Efficiency Matters

Structured text files (YAML, JSON, source code) consist primarily of
alphanumeric characters (`a-z`, `A-Z`, `0-9`, `-`, `_`, `.`, `~`), which
`encodeURIComponent` leaves unencoded. Percent-encoding avoids Base64's
mandatory 33% byte expansion, yielding **10–25% smaller data URIs** for standard
benchmark configs.

## 4. ZIP Archive Packaging & Download Pipeline

When an user or API client requests a benchmark ZIP export
(`GET /api/results/:runId/export`), `createRunZipBuffer` in
`server/results/exporter.ts` unpacks the constituent stage YAMLs and inline
`data:` URIs:

1. **Stage YAML Reports**: Dissected from `entries[].raw_report` and serialized
   to `benchmark_report_v0.2,_stage_${i}_lifecycle_metrics.json.yaml`. Reports
   sharing a stage index add a numeric suffix before `.json.yaml` after the first
   report, so both browser and API archives retain every report.
2. **Root Manifests**: Entries in `payload.manifests` containing `data:` URIs
   are decoded and unpacked into the root directory of the archive
   (`<archive_name>/<key>`).
3. **Evidence Subfolder**: Entries in `payload.evidence` containing `data:` URIs
   are decoded and unpacked into the `evidence/` subfolder of the archive
   (`<archive_name>/evidence/<key>`).

### Archive Directory Structure Example

```
llm-d-tpu-v6e-findings-20260731-e2bb0924.zip
├── benchmark_report_v0.2,_stage_0_lifecycle_metrics.json.yaml
├── benchmark_report_v0.2,_stage_1_lifecycle_metrics.json.yaml
├── config.yaml                     # Unpacked from payload.manifests["config.yaml"]
├── run_metadata.yaml               # Unpacked from payload.manifests["run_metadata.yaml"]
└── evidence/                       # Unpacked from payload.evidence
    ├── tpu-server.log
    └── summary_prometheus_metrics.json
```

## 5. UI Integration & Validation Auto-Pass

1. **Validation Warnings**: Auto-populating `manifests` and `evidence` with
   inline `data:` URIs satisfies validation rules in `benchmarkValidator.js`,
   automatically removing warning badges from the submission page.
2. **Inline Inspector**: In the UI submission inspector
   (`SubmitValidationPage.jsx`), `data:` URIs are recognized so contributors can
   view, copy, or download embedded file contents directly without treating them
   as raw web links.
